# 기기·계정 UI/UX 통일 (#178)

기존 회원 화면의 위치와 조작 흐름을 UUID 기반 기기·계정 화면에도 적용한다. 서버 ID 경로와 저장소, 계정 격리, 로그인 없는 사용은 그대로 유지한다.

## 적용 순서

1. 앨범 목록·생성: `AlbumScaffold`, 기존 `AlbumItemCard`, `CreateAlbumContent`를 공유한다. 드로어에서 기기 앨범 / 계정 앨범 / 계정·저장 공간을 선택한다. UUID 생성은 `LibraryCreateAlbumDestination(account)`에서 처리한다. 성공 시 목록으로 돌아가며 요청 이후 새 입력은 남긴다. 로그인 안내를 다녀와도 초안을 보존한다.
2. 앨범 상세: 큰 상단 바, 서브앨범·멤버·설정 하단 탭, 미리보기 카드, 선택 편집, 개별 설정과 대표 이미지 화면을 공유한다.
3. 사진: 정사각형 그리드·선택 삭제·메뉴와 전체 화면 뷰어·BottomSheet를 공유한다.
4. 통합: 밝은/어두운 테마 비교, 오프라인·계정 변경·시스템 바·업데이트 회귀를 확인한다.

## 데이터와 권한

표현 컴포넌트는 표시 값과 기능 활성 조건, 콜백만 받는다. UUID를 서버 ID로 변환하지 않는다. 서버 멤버 권한은 계정 자료에만 적용하고, 기기 자료는 로컬 소유권으로 편집한다.

계정 생성 시 선택한 친구 닉네임은 요청 시점의 계정과 함께 `CREATE_ALBUM` 작업의 `extra` JSON 배열로 저장한다. 기존 빈 `extra`는 초대 없음이다. 기기 생성과 로그인만으로 서버에 자료를 전송하지 않는다.

계정 연결은 별도 화면이다. 기기 자료와 작성 중인 초안은 전환하거나 업로드하지 않는다. 공유는 선택한 앨범의 명시적 복사 후 사용한다.

## 범위와 검증

각 단계는 최신 develop의 별도 브랜치/PR로 테스트·빌드·Lint·자체 리뷰 후 병합한다. 실제 기기는 `cord.eoeo.momentwo.migrationcheck`만 사용하며 기존 앱을 보존한다. 백엔드가 중단되어 실제 서버 회귀는 #150에 남긴다. 검색·사진 이동·Profile·#163 디자인시스템은 이번 변경 범위가 아니다.

## 상세 화면 구현 계약

서브앨범 카드의 미리보기는 같은 부모의 저장된 사진 4개까지 실제 ID와 URI로 관찰한다. 선택은 UUID 집합이며 일괄 삭제 완료는 제출한 ID만 뺀다. `deleteSubAlbums(albumId, ids)` / `deletePhotos(subAlbumId, ids)`는 모든 부모와 소유권을 검사하고 한 transaction에서 행과 outbox를 변경한다. 미확정 생성의 서버 반영 여부가 불명확하면 전체를 되돌리고 사용자 확인을 요구한다.

제목과 부제목은 별도 쓰기 계약으로 저장 시점의 다른 필드를 유지한다. 기존 두 필드 편집 초안은 복원 호환용으로 유지한다. 대표 이미지는 미리보기 후 적용하고 뒤로가기에서는 선택을 취소한다.

기기 멤버 탭은 공유 안내를 제공한다. 서버 연결된 계정 앨범의 멤버 조회/초대/추방/탈퇴는 UUID 소유 계정과 세션 epoch를 확인한 클라이언트로 수행한다. 이 온라인 작업은 자동 재전송하지 않는다. 기기 앨범의 로컬 소유권은 서버 ADMIN 값으로 치환하지 않는다.

## 사진 화면 구현 계약

사진 그리드는 같은 `PhotoGridTile`과 상단 메뉴를 사용하며 부모 UUID로 선택 항목을 일괄 삭제한다. 업로드·가져오기 중 상태와 실제 refresh 상태를 표시하며 타이머로 로딩을 흉내 내지 않는다. 입력과 선택은 최신 State에 결과를 반영한다.

`PhotoViewer`는 같은 전체 화면 이미지와 상단/하단 오버레이를 렌더링한다. 기기 하단은 설명 / 즐겨찾기 / 개인 메모 / 갤러리 내보내기, 계정 하단은 설명 / 공유 좋아요 / 공유 댓글 / 내보내기이다. 계정 사진의 개인 기록·즐겨찾기는 더보기 메뉴에서 사용한다. 개인 즐겨찾기에는 공유 수치를 표시하지 않는다.

설명 Sheet는 `PhotoDescription.read`로 첫 줄 제목과 나머지 본문을 표시한다. 읽기만으로 문자열을 저장하지 않는다. 기존 caption 초안은 읽어 분리하고 다음 명시적 저장부터 제목/본문을 기존 문자열 형식으로 합친다. 알려지지 않은 작성자·날짜·사진은 숨긴다.

`RecordsSheet`와 `RecordRow`는 개인 메모와 공유 댓글의 입력·목록·길게 누르는 편집 메뉴를 공유한다. Paging 수집/오류/추가 페이지는 기존 댓글 Route가 유지하고 UUID 메모/댓글 저장은 각 요청과 작성자 권한으로 분리한다. 시스템 바는 지속 State와 lifecycle에서 적용·복원한다.

## 통합 리뷰

UUID 앨범 생성 완료는 기기/계정 앨범 목록으로 이동한다. 뒤로가기는 원래 진입 화면을 유지하고, 제출 이후 새 초안이 있으면 완료 이동을 보류한다. 생성 초안의 원래 키는 유지하면서 목록 ViewModel의 이전 생성 업무를 별도 생성 ViewModel로 옮겼다. 초안 복원 실패는 입력을 덮어쓰지 않고 재시도하며, 같은 계정 재인증은 epoch만 갱신하고 다른 계정으로는 기존 초안을 제출하지 않는다.

계정 앨범의 조회는 사용자가 계정 목록을 열었을 때 수행한다. 캐시를 먼저 표시하고 당겨서 새로고침하며, 동기화 안내나 불러오기 버튼이 카드 본문의 위치를 밀어내지 않는다. 로그인 자체와 기기 목록은 계정 콘텐츠를 조회하지 않는다.

최초 사진 목록이 미확보 상태여도 저장된 앨범·서브앨범 제목은 상단 바에 표시한다. 본문은 필수 결과에 따른 Loading/Error를 유지하며 소유권을 잃으면 제목도 제거한다.

전체 단위 테스트·Debug/Release 빌드·Lint와 별도 앱 기기 회귀를 실행한다. `LibraryUiParitySmokeTest`는 같은 저장 자료로 기기/계정 UUID Route의 목록·생성·상세·설정·대표 이미지·사진 그리드·뷰어·설명·개인 메모 9개 화면을 밝은/어두운 테마에서 비교할 PNG 36개를 생성한다. 서버 경로는 별도 탐색·Paging·lifecycle 검증으로 유지하며 실제 서버 자료 비교는 #150에서 이어간다.
