# Offline-First 저장·복사·복구 가이드

기본 진입은 내 로컬 앨범이다. 가입·인증·콘텐츠 API 없이 앨범→서브앨범→사진→설명·개인 메모를 관리한다. [승인 계획과 검증 기록](offline-first-plan.md), [MVI 규칙](mvi-guide.md)을 함께 따른다.

## 저장 공간과 완료의 의미

| 자료 | 저장 위치·수명 | 완료 기준 |
|---|---|---|
| 기기 앨범·서브앨범·설명·메모·즐겨찾기 | Room, `libraryId=device` | 로컬 transaction 저장 |
| 직접 가져온 사진·대표 사진 | `filesDir/library-media`, 앱 소유 영속 파일 | 파일 검증·fsync·이동 및 DB 연결 완료 |
| 계정 캐시·변경 | `account:<canonical accountId>`별 Room 자료 | 로컬 저장 완료, 서버 처리 상태는 별도 |
| 내려받은 서버 사진 | `cacheDir/server-media` | 캐시가 있는 범위에서 오프라인 열람 |
| 계정 전송 작업·연결·보관 파일 참조 | Room `sync_job/link/media_pin/batch` | 계정별 영속 작업; 불명확 결과는 확인 대기 |
| 세션·편집 초안 | Preferences DataStore | 세션 원자적 저장 / 의도 토큰 조건부 초안 정리 |

직접 가져온 사진은 캐시 정리로 지우지 않는다. 원본 URI 접근이 해제되어도 앱이 보관한 파일을 사용한다. 파일이나 DB 저장 실패·취소는 성공으로 표시하지 않으며 이미 연결된 파일은 보상 정리로 삭제하지 않는다. 갤러리 내보내기는 새 복사본을 만들며 가져온 원본은 변경하지 않는다. 앱 데이터 삭제·앱 제거는 앱 내부 자료를 삭제하는 동작이다. 별도의 전체 라이브러리 백업·복원 기능은 이번 범위에 포함하지 않는다.

## 선택 계정과 복사

1. 계정 연결 메뉴에서 로그인한다. 로그인 자체로 로컬 자료 업로드나 계정 콘텐츠 조회를 시작하지 않는다.
2. 계정 앨범은 사용자가 불러오거나 저장된 캐시를 열 수 있다. 친구·공유·멤버 관리는 계정 연결이 필요하다.
3. 기기 앨범 복사·동기화에서 대상 계정과 앨범을 선택·확인한다.
4. 하나의 Room transaction으로 시작 시점의 앨범·서브앨범·사진·설명을 별도 UUID 트리와 의존 작업으로 저장한다. 복사 진행 중 복사본의 서버 변경 편집을 제한한다.
5. 원본과 계정 복사본은 독립적이다. 원본 삭제·편집이 복사 스냅샷을 바꾸지 않는다. 필요한 파일은 복사본 및 작업 참조로 보존한다.

개인 메모·즐겨찾기는 복사하지 않는다. 계정 사진에도 개인 메모·즐겨찾기와 공유 댓글·좋아요는 별도 기능이다. 계정별 동일 서버 ID·닉네임·대기 작업을 격리하며 로그아웃은 원본이나 저장된 계정 작업을 삭제하지 않는다. 같은 계정으로 로그인하면 승인된 대기 작업을 이어간다.

## 작업 상태와 사용자 조치

| 표시 | 처리 |
|---|---|
| 동기화 대기 | 기기 저장 완료. 연결 가능한 시점에 처리 |
| 계정·서버 확인 중 / 전송 중 | 영속 claim과 계정 epoch 확인, 의존 작업 순서 유지 |
| 생성 완료·항목 연결 확인 필요 | ID 없는 기존 생성 API 때문에 실제 항목을 선택해 연결 |
| 반영 여부 확인 필요 | 응답 유실·취소·프로세스 종료 경계. 자동 재전송하지 않음 |
| 서버 값과 내 변경 선택 필요 | 최신 서버 값을 다시 확인하고 선택. 값이 또 바뀌면 재확인 |
| 인증·권한·대상 확인 필요 | 계정 자료와 원본 보존. 인증은 같은 계정 로그인 후 이어가기 |
| 처리 완료 / 중단됨 | 완료와 중단을 구분해 기록 |

서버 항목은 제목만으로 추측하지 않는다. 사용자가 확인 가능한 목록·사진·ID에서 선택하며 이미 다른 UUID에 연결된 항목은 제외한다. 재전송 확인은 중복 생성 가능성을 안내하고 명시적으로 선택할 때만 수행한다. 복사 중단은 로컬 복사본과 남은 전송만 중단하며 이미 서버에 생성된 항목을 자동 삭제하지 않는다. 반영 여부가 불명확한 작업이 있으면 먼저 서버 확인을 요구한다.

조회 실패는 저장된 콘텐츠와 입력을 유지한다. 계정 변경은 로컬 변경과 작업을 같은 transaction에 저장한다. 아직 전송하지 않은 생성 트리는 취소할 수 있다. 권한은 실제 서버 멤버 권한으로 확인하며 로컬 편집을 위해 가짜 ADMIN을 만들지 않는다.

## 요청과 재시작 경계

- 계정 요청은 소유자·로그인 epoch·자격 정보를 캡처하고 실행 전후 확인한다. 전환한 계정의 DB·화면에 오래된 응답을 반영하지 않는다.
- `QUEUED → PREPARING → SENDING`을 먼저 영속 저장한다. `PREPARING` 중단은 재조회하며 서버 쓰기 시도 이후에는 `UNKNOWN`으로 보관한다.
- 이미지 객체 업로드 단계와 콘텐츠 레코드 전송 단계를 구분한다. 객체 준비만 하던 작업은 다시 준비할 수 있지만 레코드 전송 가능성이 있으면 확인 대기로 남긴다. 객체만 업로드된 실패의 서버 잔여 파일 정리 정책은 #150에서 확인한다.
- 취소는 실패 UI·Effect로 바꾸지 않는다. 현재 claim의 등록만 정리하며 이전 claim은 새 작업을 완료/정리하지 못한다.
- JobScheduler는 네트워크 제약·백오프·persisted 작업으로 사용자가 승인한 계정 작업만 이어간다. 같은 작업 ID를 실행 중 재등록하지 않고 완료 후 후속 요청을 반영한다. [Android JobInfo](https://developer.android.com/reference/android/app/job/JobInfo.Builder#setPersisted(boolean)), [JobService](https://developer.android.com/reference/android/app/job/JobService).
- 로컬 사용은 계정 작업을 만들지 않는다. 서버 장애·인증 만료는 로컬 사용을 중단하지 않는다.

## DB와 경로 호환성

Room schema v1~v4와 명시적 migration을 저장한다. 파괴적 초기화를 사용하지 않는다. 과거 소유 계정을 증명할 수 없는 서버 캐시는 원본으로 채택하지 않으며 device 자료·Profile을 보존한다. v3→v4 연결 초기화는 이미 귀속된 계정 행만 대상으로 한다.

UUID가 클라이언트 콘텐츠의 식별자이며 서버 ID는 별도 nullable 연결이다. 기존 `@Serializable` 서버 경로의 이름·인자는 유지했다. Room/파일/계정 작업은 Core에서 소유하며 UI는 분리된 State/Event/Action/Effect/Reducer/ViewModel을 사용한다.

## 검증 범위

Fake 응답·가상 시간, 실제 Room migration과 transaction, 파일 저장·원본 URI 해제·갤러리 내보내기, 실제 Compose lifecycle/Effect/Paging 및 별도 앱 비행기 모드를 검증한다. 외부 force-stop을 사이에 둔 두 instrumentation에서 사진·기록 복원을 확인한다. 기존 앱은 삭제하거나 초기화하지 않는다.

백엔드 배포 중단으로 실제 로그인·계정 복사·공유·서버 충돌 회귀는 [#150](https://github.com/Momentwo/Momentwo/issues/150)에 남긴다. 실제 기기 전체 재부팅 및 OS 백업·복원은 실행하지 않았다. DB reopen·프로세스 종료 검증을 물리 기기 재부팅 검증으로 표현하지 않는다.


별도 applicationId로 앱과 androidTest APK를 빌드·설치한 뒤 아래 명령으로 실제 비행기 모드 전체 회귀와 process-seed → 외부 force-stop → process-verify를 실행한다. `--fresh`는 별도 앱만 초기화하며 기본값은 기존 자료 보존이다. 스크립트는 원래 앱 패키지를 거부하고 성공·실패 모두 기존 비행기 모드를 복원한다.

```bash
python3 scripts/verify-offline-device.py --adb "$ANDROID_HOME/platform-tools/adb" --serial <serial> --fresh
```

applicationId 변경용 Gradle init script는 기기 검증 환경에서만 사용하고 제품 코드에 포함하지 않는다. 일반 `connectedDebugAndroidTest`는 제품과 같은 applicationId이므로 원래 설치 앱을 보존할 때 이 격리 절차를 사용한다.
