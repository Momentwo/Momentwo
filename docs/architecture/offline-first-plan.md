# 계정 없는 Offline-First 전환 (#162)

2026-10-14 승인 계획. 처음 설치한 기기에서도 가입·로그인·연결 없이 앨범, 서브앨범, 사진, 설명·메모·즐겨찾기를 관리한다. 로컬 저장이 완료되면 작업은 완료다. 서버 전송이나 로그인을 기다리지 않는다.

## 제품 규칙

- 로컬 라이브러리는 정식 기본 사용 방식이며 계정은 공유·친구·계정 앨범을 위한 선택 기능이다.
- 앱은 로컬 앨범으로 시작한다. 계정 연결은 사용자가 선택할 때만 수행한다.
- 직접 가져온 사진은 앱 영속 파일로 보관하며 캐시 정리로 삭제하지 않는다. 원본은 수정하지 않는다.
- 로컬 CRUD는 콘텐츠 API·인증·서버 권한 조회 없이 완료한다. 로컬 소유권을 서버 ADMIN으로 표현하지 않는다.
- 개인 메모·즐겨찾기는 공유 댓글·좋아요로 자동 변환하지 않는다.
- 로그인만으로 업로드하지 않는다. 선택한 앨범·서브앨범·사진·설명만 시작 시점의 스냅샷으로 계정에 복사한다. 로컬 원본은 유지하고 이후 독립적으로 편집한다.
- 계정별 저장소·대기 작업을 격리한다. 인증 만료/계정 전환이 로컬 사용을 중단하지 않는다.
- 계정 생성 결과/반영 여부를 확정할 수 없으면 사용자 확인을 요구한다. 이름만으로 연결하거나 불명확한 쓰기를 자동 재전송하지 않는다.

## 구현 계약

- library와 안정적 UUID localId가 기준이다. serverId는 별도 nullable 연결 정보다.
- Repository는 로컬 관찰·변경과 선택적 동기화를 분리한다. #155의 순수 Reducer와 취소 보존 요청 기반을 유지한다.
- 기존 서버 ID 경로의 직렬화 이름/인자를 유지하며 로컬 UUID 경로를 추가한다.
- Room schema와 migration을 버전 관리하고 destructive fallback을 제거한다. 소유자가 불명확한 과거 네트워크 캐시는 로컬 원본으로 채택하지 않는다.
- 파일이 준비되고 DB 저장까지 성공해야 사진 추가가 완료된다. 취소/저장 실패/URI 만료/공간 부족에서 기존 자료를 보존한다.

## 별도 브랜치·PR 순서

모든 base는 develop이며 검증·자체 리뷰 후 Draft → Ready → 병합한다. 앞 PR 병합 후 최신 develop에서 다음 브랜치를 만든다.

1. `refactor/offline-local-foundation`: 라이브러리/UUID·Room v2와 명시적 migration·로그인 없는 진입
2. `feat/offline-local-albums`: 앨범/서브앨범/대표 이미지/설정의 로컬 CRUD
3. `feat/offline-local-photos`: 영속 사진 추가·열람·삭제·내보내기, 설명·메모·즐겨찾기
4. `feat/offline-account-connection`: 선택적 로그인·계정별 자료·친구/공유 연결
5. `feat/offline-account-sync`: 선택 앨범 복사·영속 작업·재시작·충돌·불명확 결과/인증 복구
6. `test/offline-integration`: 전체 통합 검증·README·가이드·이슈 정리

1~3단계에서 계정 없는 핵심 사용을 완성하며 백엔드를 기다리지 않는다. 기존 API와 라이브러리 버전을 유지한다. 실제 서버 복사/공유/동기화는 백엔드 복구 후 #150에서 확인한다. 사진 이동·검색·계정 찾기·Profile 전체 구현 등 미구현 기능은 별도 범위다.

## 검증

- 새 설치/비행기 모드/로그인 이력 없음에서 로컬 생성·편집·삭제, API 요청 0
- 재시작·DB reopen·기기 재부팅·캐시 정리에서 원본과 UUID/관계 보존
- migration·파일/DB 저장 경계·취소·공간 부족·URI 접근 상실·계정 격리
- 로그인 취소/실패/만료/로그아웃과 선택 복사·부분 실패·충돌·결과 불명
- 영향 모듈 테스트·빌드·Lint와 별도 applicationId 기기 확인. 원래 설치 앱은 보존한다.

- 단계 1 구현: library/local_album/local_subalbum/local_photo/local_memo 테이블과 v1→v2 migration. 미귀속 photo/friend 캐시만 초기화하며 Profile identity는 유지한다. 기본 그래프는 로컬 라이브러리이며 계정 연결이 기존 Auth로 이동한다. 초기 CRUD 화면은 다음 단계에서 확장한다.

- 단계 1 검증: 단위 테스트 126개(기존 123+신규 3), app/영향 모듈 빌드·Lint 통과. SM_N976N API 31 별도 패키지 신규 설치 상태 기기 5개 통과: 첫 진입 API 시도 0, migration, DB 재열기/cascade, 라이브러리 변경 차단, 계정 연결/Auth 이동.

- 단계 1 PR #172 병합 완료. 단계 2는 로컬 앨범/서브앨범 생성·수정·삭제, 소제목과 영속 대표 사진, DataStore 편집 초안 복원을 추가한다. 생성 의도 UUID를 저장해 프로세스 재진입의 중복 생성을 막는다. DB에 연결된 파일은 취소 후에도 유지하며 파일 정리는 메타데이터 저장 결과와 구분한다.
